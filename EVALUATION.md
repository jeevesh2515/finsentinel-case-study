# Evaluation

## Evaluation goals

1. Prove the pipeline works end-to-end on synthetic data: ingest, process, triage, retrieve evidence, draft, review, and export.
2. Record reproducible, attributable measurements for latency, throughput, and grounding instead of adjectives.
3. Keep evaluation honest: every published number states its dataset, date, gate, run type, and limitations.
4. Make the evaluation itself a safety boundary: figures that cannot meet this standard are withheld.

## Dataset description

- Synthetic transactions generated by a seeded, deterministic generator with annotated typologies and look-alike normal cases.
- The end-to-end benchmark uses a 50-event synthetic ingestion run.
- The pilot-pack evaluation uses 10 synthetic cases across triage bands, exercising pack preparation, citation grounding, and abstention.
- The *pilot kit* is an internal evaluation package prepared for prospective customer pilots. No pilot has been run, and no customer has used the product.
- Regulatory guidance in the recorded gates comes from a small versioned stub registry with content hashes; it is not a full regulatory corpus.
- **No real customer data, real alerts, or production records were used anywhere.** All data is synthetic.

## Metrics and definitions

| Metric | Definition |
|---|---|
| Unit / integration tests | Counts reported by the project test runner at the recorded gate, including parameterised cases |
| Ingestion throughput | Accepted events per second through the REST intake on a warm local stack |
| Consumer scoring | Mean milliseconds per event to compute features and produce a score in the background processing path |
| Workflow execution | Mean milliseconds per event for the full multi-step processing pipeline |
| Dashboard p50 | Median response time of the analyst dashboard overview query |
| Pack preparation p50 | Median milliseconds to build an exportable investigation pack for a high-priority case |
| Citation grounding | Fraction of citations in generated drafts that match a verified source chunk (verified / total) |
| Provider spend | USD actually charged by external model providers during the gate |

## Verified results

All results below are from a single Apple Silicon macOS development machine running the local stack in mock-only mode. They describe the synthetic test setup and do **not** predict real-world fraud-detection performance.

### 1. Test suite (2026-10-17 re-verification)

- **Value:** 288 unit tests passing; 86 integration tests passing (against a disposable local PostgreSQL instance).
- **Dataset scope:** synthetic fixtures and disposable test databases.
- **Test date:** 2026-10-17 local re-verification on `main` after all roadmap phases were accepted and the internal pilot kit was packaged.
- **Identifier:** after-acceptance local re-verification sweep; internal commits omitted (source repository is private).
- **Run type:** local, synthetic.
- **Limitations:** a green local suite is not production proof, uptime, or a substitute for independent security testing. Counts grow over time; the count at the 2026-10-12 pilot-kit gate was 285 unit / 86 integration.

### 2. Ingestion and processing benchmark (2026-10-07, P7 gate)

Source record: the project's dated evaluation evidence for the P7 gate (2026-10-07). Machine: Apple Silicon macOS, 10 CPU cores, Python 3.12, local database container.

| Metric | Value |
|---|---|
| Synthetic events ingested | 50 |
| Ingestion throughput | 36.13 requests/second |
| Ingestion latency p50 | 26.5 ms |
| Consumer scoring | 6.49 ms/event |
| Full 5-step pipeline | 13.12 ms/event |
| Dashboard overview p50 | 27.97 ms |
| Provider spend | $0.00 (mock provider) |

- **Dataset scope:** 50 synthetic events, one run, warm caches.
- **Test date:** 2026-10-07.
- **Identifier:** P7 evaluation gate, accepted 2026-10-08; internal commits omitted.
- **Run type:** local, mock-only, synthetic.
- **Limitations:** single machine, single run, small synthetic dataset, no concurrent load, no network latency, no provider calls. A re-run on 2026-10-17 measured 35.55 req/s ingestion, 5.3 ms/event consumer scoring, 14.9 ms/event pipeline, and 27.9 ms dashboard p50. The internal 15 ms dashboard aspiration was recorded as unmet; the 100 ms working budget was met.

Source record: the project's dated pilot-pack evaluation evidence for the P9 gate (2026-10-09).

| Metric | Value |
|---|---|
| Cases | 10 synthetic |
| Cases with packs prepared | 7 |
| Cases abstained | 3 |
| Pack preparation p50 | 177.5 ms (max 188.0 ms) |
| Citation grounding | 1.0 (every citation in generated drafts matched a verified source chunk) |

### 4. Internal release checks (2026-10-12 / 2026-10-17)

- **Value:** one-command pilot smoke check passed 6/6; release preflight verifier passed 4/4 checks (environment posture, secret scan, licence, schema chain).
- **Dataset scope:** local synthetic environment.
- **Test date:** recorded at the pilot-kit gate (2026-10-12) and the 2026-10-17 re-verification.
- **Identifier:** pilot-kit and re-verification records; internal commits omitted.
- **Run type:** local, synthetic.

## Withheld results

The following were considered for publication and deliberately withheld:

| Item | Reason |
|---|---|
| Simulated per-case time saving | The underlying evidence record labels the figure as assumption-based and simulated, not measured. Publishing any number would risk being read as real-world productivity data. |
| Synthetic anomaly-evaluation figures (look-alike flag rates, contamination calibration) | They describe generator labels, not detection quality; any public wording risks being mistaken for fraud-detection accuracy. |
| Triage thresholds and scoring calibration values | Proprietary product internals; publishing them would disclose the implementation recipe. |
| Cloud cost model estimates | Modelled, not incurred; deployment was never performed. |

These items are recorded with provenance in a private review report outside this repository and can be promoted later if the author approves specific wording.

## Reproducibility limits

- Measurements come from one personal macOS machine, not a controlled benchmark environment.
- The stack is local (containers on one host); no network, multi-tenant load, or production-like conditions were exercised.
- Evaluation datasets are small and synthetic, generated deterministically but not independently reproducible by third parties because the generator is private.
- Run-to-run variance is real and shown where two runs exist.
- No third party has reproduced these results.

## Synthetic-data disclaimer

Every number in this document comes from synthetic or mock runs on a local machine. None of it is evidence of real-world AML detection, prevention, or regulatory performance. Anomaly scores are triage priorities, not fraud probabilities.

## Funding and cost statement

All recorded gates ran with paid provider access disabled and a mock provider. Provider spend at every gate was $0.00. No cloud deployment was performed; infrastructure was written and statically validated only.
